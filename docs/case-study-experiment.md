# Case study: choosing an embedding model and chunk size

A reproducible bake-off on a real RAG corpus, generated by
[`examples/experiment_demo.py`](../examples/experiment_demo.py).

**Setup.** 3,000 passages from "RAG Dataset 12000" (Neural Bridge AI, Apache-2.0; passages
from Falcon RefinedWeb, ODC-By 1.0) and 300 real questions, each labelled with the passage
it was written for. Labels are on passages, so every chunking is judged against the same
answers. Results are scored at document level, k = 10, on a laptop CPU.

| # | Candidate | nDCG@10 | Change vs leader (95% CI) | Chunks | Index | Embed corpus | Search p95 |
|---|---|---|---|---|---|---|---|
| 1 | BGE-small, 150-word chunks | **0.938** | leader | 15,363 | 22.5 MB | 69 s | 0.30 ms |
| 2 | MiniLM, 150-word chunks | 0.912 | −0.026 [−0.050, −0.004] | 15,363 | 22.5 MB | 34 s | 0.28 ms |
| 3 | MiniLM, 400-word chunks | 0.886 | −0.051 [−0.079, −0.025] | 6,069 | 8.9 MB | 14 s | 0.15 ms |
| 4 | MiniLM, 150-word chunks, HNSW | 0.867 | −0.071 [−0.105, −0.039] | 15,363 | 24.6 MB | (cached) | 0.07 ms |
| 5 | Lexical baseline | 0.612 | −0.325 [−0.376, −0.277] | 15,363 | 120.0 MB | (cached) | 1.19 ms |

## What the report says

- **BGE-small wins, and the win is real.** Every other candidate's interval excludes zero:
  the gap isn't noise on these 300 questions. It wins both cohorts (long and short
  passages).
- **The model matters more than the chunk size here.** Switching MiniLM → BGE-small at the
  same chunking gains 0.026 nDCG for twice the embedding time.
- **Bigger chunks are cheaper and worse.** 400-word chunks cut the index by 60% and
  embedding time by 60%, and cost 0.026 nDCG against 150-word chunks of the same model.
  Whether that trade is worth it is now a business decision with numbers attached.
- **The approximate index has a measurable price.** HNSW at `efSearch=16` is 4× faster to
  search but finds only 82% of the exact neighbours, costing 0.045 nDCG against exact
  MiniLM search: a release check would flag that as approximation loss and suggest a
  higher `efSearch`.
- **Semantic models beat lexical matching by a wide margin** (0.94 vs 0.61), the floor any
  embedding choice should clear.

## Then

The winner's results are a normal run file (`runs/bge-small-150w.json`). Pinned as the
baseline, release checks guard the choice from then on: a later change of chunker, index
parameters or model version has to beat or match 0.938 on the same questions.

```bash
uv run python examples/experiment_demo.py --out experiment-demo
```

Timings depend on the machine; quality numbers are deterministic for the same models and
seed. Re-runs reuse cached document embeddings.
