# Decisions log

One line per non-obvious technical decision.

- Dev environment pinned to Python 3.12 (`.python-version`); `requires-python>=3.10`. System Python 3.14 may lack faiss-cpu wheels.
- `httpx` added to the `dev` extra: FastAPI's `TestClient` requires it.
- `__version__` is read from installed package metadata so `pyproject.toml` is the single source of truth.
- Frontend pinned to React 18 (per plan) although the Vite template defaults to 19.
- Vite `base: './'` (relative asset URLs) so the built UI works under path-prefixing proxies (Jupyter/Colab/HF Spaces).
- Tailwind v4 via `@tailwindcss/vite` plugin (no PostCSS/tailwind.config needed).
- `static/` is gitignored but force-included in wheel and sdist via hatch `artifacts`; the frontend must be built before `uv build`.
- Synthetic builders live in `examples/make_synthetic.py`; `tests/conftest.py` imports it by path so demos and tests share one code path (at smaller n/nlist).
- mypy has no `python_version` pin: numpy>=2.5 stubs use 3.12-only syntax. Each CI matrix job typechecks against its own interpreter instead.
- `LoadedIndex.index` holds the owning root object; `core`/`ivf` are non-owning `downcast_index` views that dangle if the root is garbage-collected.
- IVF core is found by unwrapping PreTransform/IDMap/Refine ourselves and checking `isinstance(core, IndexIVF)`, not `extract_index_ivf`, so `kind`, `core` and `ivf` always agree.
- `d` is the input dimension (what queries use); `core_d` is the dimension after any PreTransform (what centroids/codes use).
- Binary, GPU, FastScan, non-L2/IP metrics and other exotic indexes load as `UNSUPPORTED` with a reason instead of raising.
- IVF centroids of a PreTransform index are returned in the transformed space (`core_d`); anything comparing them to raw vectors must apply the transform first.
- `list_members`/`assignments` read ids via `invlists.get_ids` directly instead of `inspect_tools.get_invlist`, which also copies every list's codes.
- `imbalance_factor` returns 0.0 for an empty index (FAISS returns NaN, which isn't valid JSON).
- Search parameters go through `SearchParametersIVF/HNSW` per call, never by mutating `nprobe`/`efSearch`. `IndexRefine` needs them wrapped in `IndexRefineSearchParameters` with the index's own `k_factor` (its default of 1 would change results).
- Self-exclusion searches k+1 and drops the query's own id, so the caller still gets k results.
- New `core/vectors.py` (not in the original layout): `VectorSource` holds input-space vectors sorted by user id, whether raw or reconstructed; ground truth, query-by-id, projection and PQ error all share it.
- Reconstruction enables a direct map on IVF indexes (array for sequential ids, hashtable for `add_with_ids` ids). This mutates the index object but not its search results (tested).
- Reconstructed vectors for PreTransform indexes are mapped back to input space with `reverse_transform`, which is lossy for PCA.
- `vectraudit.core` does not re-export the `search` function: it would shadow the `core.search` submodule (`from vectraudit.core import search` would return the function). Use `core.search.search(...)`.
- Projections are computed in core space (after PreTransform) so points, IVF centroids and queries share one space.
- PCA uses `eigh` on the d×d covariance rather than an SVD of the data (~5x faster for n >> d); component signs are normalised for determinism.
- UMAP queries are placed by inverse-distance-weighted kNN interpolation over the projected sample, not `umap.transform` (4.7 s for 10 queries on 20k points). Centroids use `.transform` once at fit time and are cached.
- Projection cache key = index sha1 (dir) + method + dims + max_points + seed + sha1 of the sampled vectors, so raw vs reconstructed vectors never collide. Stored as `.npz` (no pickle), written atomically. `VECTRAUDIT_CACHE_DIR` / `XDG_CACHE_HOME` override the location.
- UMAP tests are marked `slow` (cold numba import ~35 s) and excluded by default; CI runs them with `-m "slow or not slow"`.
- `Session` lives at package level (not in `core`) but has no web imports; the server and `launch()` both wrap it.
- Session caches are computed on first use under an `RLock`. Building an IVF direct map during reconstruction is safe alongside searches: IVF search never reads the direct map, and building it only reads the inverted lists.
- A `--embedder` model name loads in a background job at startup (importing sentence-transformers takes ~15 s); the first text query waits for it. Query embeddings are normalised iff the raw vectors are unit-norm (or, without raw vectors, iff the metric is IP), unless overridden.
- The session resolves its cache directory at construction, not in the background thread, so env changes can't redirect a running job (tests caught stray writes to ~/.cache).
- Projection responses are columnar (`ids`, `x`, `y`, `z`, `list_nos`) with coordinates rounded to 4 decimals: smaller JSON than `[[x, y], ...]` and maps directly onto deck.gl attributes.
- `/api/search` takes an optional `projection: {method, dims}`; if that projection is ready, the response includes the query's coordinates. The UI can't place text queries itself, since it never sees vectors.
- Unknown `/api/*` paths return JSON 404s; all other unknown paths fall back to `index.html` for client-side routing. Without a built frontend, `/` serves a short "run npm run build" page.
- OpenAPI docs are served at `/api/docs` so they don't collide with SPA routes.
- Cluster-map points are not coloured per IVF list: 128+ lists can't get distinguishable categorical hues (the dataviz rules forbid cycling past 8). Points are neutral, the focused list is highlighted in series blue, and "by list size" uses the sequential blue ramp.
- Query map uses three validated categorical slots (blue returned, orange missed true neighbour, ink query target); miss reasons use status colours, always with an icon and a label.
- Colour roles live as CSS variables (index.css) with dark steps chosen for the dark surface, mirrored in `lib/theme.ts` for deck.gl, which needs RGB arrays.
- Hash routing (`#/query?id=42&nprobe=4`) instead of a router dependency; URLs are shareable and "Query →" links auto-run.
- Map views are `React.lazy` chunks so deck.gl (~600 kB) loads only when a map opens; recharts ships with the Overview.
- The query map opens framed on the query, its results and its missed neighbours; "Reset view" shows all points.
- Recharts animations are off (charts must not flash or re-animate on refetch). Probe-chart dots share the line's dataset, because a separate scatter dataset drives the y-domain on its own and clips the line.
- `ScatterMap` derives its fitted view state during render and keeps user pan/zoom keyed to that framing, instead of calling setState in an effect.
- Frontend tests (Vitest, Playwright) are listed in the plan's testing section but not in its dependency list; deferred until approved.
- Sweeps time each query individually around `index.search` only (no Python result handling inside the timed region), after one untimed warm-up pass, with FAISS pinned to 1 OpenMP thread. The pin is process-wide, so timed sweeps are serialised by a lock, and the previous thread count is restored even on error.
- `recommend(target)` picks the smallest parameter value that meets the target recall, not the lowest measured latency, because latency is noisy and cost grows with the parameter.
- Like `search`, the `sweep` function is not re-exported from `vectraudit.core` (it would shadow the `core.sweep` module); call `core.sweep.sweep(...)`.
- Sweep jobs are keyed by (param, sorted values, k, n_queries) and addressed by a 12-char sha1 `job_id`; re-POSTing the same sweep returns the existing job (200 once done), so reloads don't re-run it. Values are validated before a job starts so errors surface as immediate 400s.
- Tuner charts: recall, latency and recall-vs-latency are three separate single-axis charts (never dual-axis). The x-axis is log2 when values span 8x or more. Only the endpoints and the recommendation are direct-labelled; the table is the full text twin.
- The "Apply it" snippet recommends `faiss.ParameterSpace().set_index_parameter`, verified (and tested) to work through IDMap, PreTransform and Refine wrappers and on HNSW.
- Vitest (approved) covers the frontend's pure logic (`lib/*.test.ts`); CI runs typecheck, oxlint, Vitest and the build.
- Playwright (approved) runs one smoke spec (overview, query explorer, tuner) against `vectraudit serve` on a 2k synthetic index, in its own CI job. Vitest is scoped to `src/**/*.test.ts` so it never picks up the Playwright specs.
- `vectraudit serve`'s port pre-check sets `SO_REUSEADDR` like uvicorn: a just-closed port in TIME_WAIT counts as free, a live listener does not. Without it, quick restarts failed with "port in use".
- `Viewer` binds its own listening socket (port 0 = OS-chosen) and hands it to `uvicorn.Server.run(sockets=...)` in a daemon thread: no check-then-bind race, and uvicorn skips signal handling off the main thread, so it's safe inside a notebook kernel.
- `launch()` opens a browser only outside notebooks, and never when `VECTRAUDIT_NO_BROWSER=1` (CI, scripts). In notebooks, displaying the viewer embeds an iframe; in Colab it uses `serve_kernel_port_as_iframe`, since Colab can't reach the kernel's localhost. `VECTRAUDIT_PROXY_URL` (e.g. `/proxy/{port}/`) supports jupyter-server-proxy on JupyterHub; the UI's relative URLs make that work.
- IPython isn't a dependency: notebook detection reads `sys.modules`, and `IPython.display` is imported only inside `_ipython_display_`.
- HNSW node levels are exposed 0-based (FAISS stores `level + 1` in `hnsw.levels`); graph arrays are copied out with `vector_to_array` because `inspect_tools.get_hnsw_links` is not available in faiss 1.15.
- HNSW trace level 0 models `faiss::search_from_candidates` rather than textbook HNSW: a bounded "minimax" candidate queue whose popped entries keep occupying slots, a separate top-k heap over every evaluated node, and the `count_below(d0) >= efSearch` stop. In faiss 1.15 the queue capacity is `efSearch` itself, not `max(efSearch, k)`; measured, matching it takes overlap from 0.62 to 1.00 at efSearch=4 < k=10. Overlap is 1.00 on hard queries for efSearch 4–256, L2 and IP, with and without IDMap.
- Because the top-k is kept over all evaluated nodes, an HNSWFlat miss always means "not reached from the visited frontier"; "visited but not kept" only arises with lossy SQ/PQ storage or ties.
- The trace uses storage vectors decoded with `reconstruct_n`; for SQ/PQ storage FAISS's own distance computer can differ slightly (tested overlap >= 0.9 on HNSW-SQ8).
- Session lazy values each get their own lock (`_once`). A single session-wide lock deadlocked when a lazy value (the HNSW layout) waited on a background job that itself needed another lazy value; a regression test covers it.
- HNSW node positions reuse the session's 2D PCA (fitted on the stored vectors), applied to every node, so the graph view lines up with the cluster map. `/hnsw/graph` returns each undirected link once. Level 0 is sampled by BFS from a chosen node (or the entry point).
- `/trace/hnsw` traces k+1 for stored-vector queries and drops the query's own id, matching `/search`. It reports FAISS's own result ids and the overlap, so the "reconstructed trace" label is backed by a number in the UI.
- HNSW view: a 3D orbit scene with one plane per level (z = level × 0.55 × layout span). Upper levels are drawn in full (up to 4k nodes); level 0 shows 1.5k nodes around the search's level-0 entry. The "Auto" camera shows the layers during the descent, then switches to a top-down close-up of level 0 framed on everything the search touched, where most of the work happens.
- Animation frames are trace steps (one node's links scanned). The frame state (visited, frontier, descent path) is recomputed from the trace by a pure function (`lib/hnswFrames.ts`, Vitest-tested). It measured 60 fps at efSearch 256.
- Quantization error compares the raw vectors with `reconstruct_all` output in input space, so PreTransform indexes include the transform's loss (reported, not separated). "Approximate distance" = distance from the exact query to the reconstruction, which equals the index's asymmetric distance for IVF-PQ/SQ.
- Distortion pairs sample each query's exact nearest neighbours plus random vectors. We report correlation over near pairs separately because random far pairs inflate it: IVFPQ(m=8) on the demo data scores 0.9994 overall but 0.72 among near pairs, which is what explains its recall ceiling.
- `/api/pq/error` returns 200 `{available: false, reason, hint}` without raw vectors: an expected state the view explains, not an error. Otherwise it follows the 202-while-computing pattern. Distortion values are rounded to 5 significant digits to keep the ~4k pairs compact.
- Quantization view: the distortion scatter defaults to near pairs only, with axes fitted to them; with all pairs, far pairs span ~70x the range and squash the near pairs into a corner. The view is in the nav for PQ/SQ indexes and indexes with a dimension-reducing transform; "Quantization" misses in the Query Explorer link to it.
- RAG demo data: "RAG Dataset 12000" (neural-bridge/rag-dataset-12000, Apache-2.0; passages from Falcon RefinedWeb, ODC-By 1.0). Chosen for its permissive licence, small download (29 MB of parquet) and built-in questions, which become sample queries. Fetched with urllib + pyarrow instead of adding the `datasets` package. Passages are chunked into 150-word (~200 token) pieces, capped at 20k chunks, and embedded with all-MiniLM-L6-v2 (normalised, IP). Full build: 88 s cold on an M-series laptop.
- Query Explorer state (id or text, k, nprobe/ef, compare) lives in the URL hash; the view runs whatever the URL describes, so results are shareable and survive reloads. Pasted vectors run without touching the URL (too long to share).
- Exports are client-side (Blob download): per-table CSV (RFC 4180 quoting, nested snippet fields flattened to `snippet.text`) and full JSON. Focus mode (the backslash key, or "Hide sidebar") and print styles hide the sidebar and controls for screenshots.
- Ground truth brute-forces with `faiss.knn` over the session's vector array instead of building an `IndexFlat` copy; results are identical and it's slightly faster. At 1M × 64 it cut RSS after searching from 873 to 635 MB and first-search latency from 56 to 8 ms; at 1M × 384 it saves 1.5 GB. `from_arrays` keeps the caller's array (no copy) when ids are already sorted, so an in-memory `launch()` shares memory with the user's array.
- The 1M-vector profile and RAM guidance live in `docs/performance.md` (RAM ≈ index + n × d × 4 B + ~100 MB, with or without raw vectors).
- The RAG demo builder lives in the package (`vectraudit/demo.py`) behind `vectraudit demo`, because pip users don't get `examples/`. It builds once into `~/.cache/vectraudit/demo-rag` (10k chunks by default, 56 s cold with the model cached), then serves the IVFPQ index with vectors, metadata, queries and the MiniLM embedder wired up. `examples/make_rag_demo.py` is a thin wrapper (default 20k chunks). IVF nlist shrinks for small corpora to keep about 40 training points per list.
- CLI errors escape Rich markup: install hints like `vectraudit[all]` were silently printed as `vectraudit`.
- `--demo-mode` (for the public HF Space) caps k at 100, efSearch at 1024, and sweeps at 200 queries, 12 values and k = 50. UMAP is served only if its projection is already in the disk cache (the Docker build precomputes it). Over-limit requests get `403 DEMO_LIMIT` with a hint; `/api/info.demo_limits` lets the UI cap its inputs and show a "Read-only demo" badge. There are no uploads to disable: vectraudit never accepts files over HTTP.

- Raw-vector IDs must equal the index's user-facing ID set (including sparse IVF IDs); mismatches previously produced plausible but false recall. Non-finite vectors and non-integer IDs are rejected at ingestion.
- API IDs retain numeric encoding in JavaScript's safe range and use decimal strings for larger int64 IDs, preserving compatibility for existing small-ID clients. Browser parsing uses BigInt before choosing the canonical numeric/string representation; HNSW trace nodes no longer pass IDs through float.
- Background jobs use two transient daemon workers, eight waiting slots, and 32 completed results with a one-hour lazy expiry. Cancellation is cooperative at progress callbacks; queued sweeps can be removed immediately. Sweep query/ground-truth caching uses a four-entry, 64 MiB LRU instead of unbounded session lazy keys.
- Sweep timings warm each setting and repeat queries three times by default in seeded order. Exports carry timing/sampling seeds, a canonical query-and-exclusion hash, and environment versions. Recall is counted once per query, independent of timing repeats.
- Index comparison starts in the core API and CLI: shared raw ground truth, identical query/exclusion sets, alternating measurement order, per-query neighbour membership changes, and serialized bytes explicitly distinguished from resident memory. The web Compare view reuses it (see below).
- Tagged releases invoke reusable CI before building/publishing; both CI and release validate an installed wheel in an isolated environment, including bundled static assets, an API query and the CLI entry point.
- `/api/search` takes an opt-in `trace` flag that embeds the IVF probe trace, so the query explorer makes one request instead of search + `/trace/ivf` (which ran the query and exact search twice). `trace` requires `compare`, since miss reasons need ground truth; with compare off the UI skips all exact work. `/trace/ivf` stays for API clients.
- Frontend requests carry a 60 s deadline (long work is already polled jobs) and an optional AbortSignal: queries use React Query's signal, and one-at-a-time searches/traces abort the previous request. Aborts are not toasted. Views sit in an error boundary keyed by view; a failed lazy chunk offers only "Reload page", since `React.lazy` caches the rejected import.
- Failed/cancelled background jobs are kept, not restarted by the next `get_or_start`: status polls (projection, PQ, embedder via /info) would otherwise turn a failure into an endless "running". Explicit actions retry: `retry=true` on /projection and /pq/error (UI "Try again"), starting a sweep, and a text query loading the embedder.
- Projection cache hits take per-point `list_nos` from the current request's assignments, not the file: the key hashes the sampled vectors, which can be identical with or without assignments, and list numbers are cheap to rebuild.
- The client rejects any 2xx body that is not a JSON object as `INVALID_RESPONSE` (every endpoint returns an object), so a proxy or login page answering 200 fails clearly. Per-endpoint schema validation is left out: it would need a validation dependency outside PLAN.md.
- Sweep recall uncertainty is a normal-approximation 95% interval over per-query recalls (clipped to [0, 1]; [0, 1] for one query). It is cheap and deterministic, but reads as [1, 1] when every sampled query is perfect: the interval covers query sampling, not unseen tail queries. The exact per-query distribution ships as `(recall, count)` pairs, since recall@k has at most k + 1 distinct values; the UI derives "queries below target" for any target from it. Worst queries (10 per setting) carry stored ids for sampled queries so the Tuner can open them in the Query Explorer.
- `recommend` stays "smallest value meeting the target" (cost grows with the parameter, latency is noisy); `fastest` reports the measured-fastest qualifying setting separately instead of replacing it.
- The web comparison only compares indexes named at startup (`serve --compare`, `launch(compare=...)`); the API never takes file paths, keeping "vectraudit never reads files named over HTTP". Candidates are validated when the server starts (raw vectors required; same d, metric and id set), so the view can't fail late on a mismatch. The main index is always the left side; comparisons reuse the sweep's cached queries and ground truth, and run as cancellable jobs like sweeps. The API returns the 200 most-changed queries (largest recall change first) plus counts; the CLI `--json` keeps every query.
- Job responses that carry ids (sweep worst queries, comparison changes) are dumped with `model_dump(mode="json")`, so ids above 2**53 - 1 become strings as elsewhere.
- Below Tailwind's `md` breakpoint (768 px: phones, narrow notebook iframes) the sidebar starts hidden and opens as an overlay that closes after navigating; the Menu button gets its own sticky bar there so it never covers a heading. Crossing the breakpoint resets the sidebar to that width's default.
- Tuner and Compare share one job hook (`api/jobs.ts`). Job ids hash the settings, so a restart reuses the id and the URL: start and cancel responses are written into the React Query cache rather than relying on navigation or refetch, which is what resumes polling. The URL also carries the run settings (`values`, `k`, `n`, `repeats`, `seed`; plus `candidate`, `left`, `right` for comparisons), so a 404 for an expired job or a restarted server becomes "Run again" with the same settings instead of a dead link.
- `--mmap` is opt-in: mapped arrays are read-only, and a file on a slow or network disk makes every exact search pay I/O. The mapping is kept only when `from_arrays` needs no copy (float32, C order, ids sorted); otherwise the reason is reported rather than failing. Keeping unsorted rows mapped would need an id-to-row permutation instead of the sorted-by-id `VectorSource` invariant; not done, the cost is measured in `docs/performance.md`. Peak memory is measured as macOS physical footprint via `proc_pid_rusage` (psutil isn't a dependency), since RSS counts clean mapped pages the OS can drop.
- The Tuner/Compare trust checklist is computed client-side from `/api/info` and the finished result (`lib/evaluation.ts`). "Enough queries" means a recall half-width of at most ±0.01 at the recommended (or best) setting, and the suggested query count scales with the square of the width ratio. Relevance (labelled query → chunk judgments) is only named, not measured: it needs a labelled-data input that vectraudit doesn't take yet.
- Large views keep their lazy-loaded entry file (`views/QueryExplorer.tsx`, `views/Hnsw.tsx`) and move their parts into a folder of the same name: request/URL state in a hook (`query/useQueryRunner.ts`, `hnsw/usePlayback.ts`), then one component per panel. Hooks and components live in separate files for React fast refresh. Number inputs share `components/form.tsx`. API routes follow the same idea: `server/routes/<feature>.py`, with shared dependencies in `common.py`.
- IVF probe coverage ranks each true neighbour's list with the coarse quantizer's own `search(q, nlist)` order, i.e. exactly the lists a search at any nprobe visits, in chunks of about 2M cells. One pass gives the coverage curve for every nprobe (`SweepResult.coverage_curve`, kept server-side), so "nprobe needed to cover the target" is read off it rather than extrapolated. An HNSW coarse quantizer orders lists approximately, so coverage there can differ slightly from what a search probes.
- Suggestions come from one module (`core/advice.py`) that the API serves for any target, instead of being mirrored in TypeScript like `recommend`: the rules need IVF list stats and index structure that only the server has. Thresholds are constants there: a curve is flat below +0.005 recall per doubling; "try larger values" is offered only if the current rate reaches the target within 3 doublings; a query fails below recall 0.5 and a tail needs 2% of queries (only for targets above 0.5); lists are uneven at imbalance factor 2 or 10% empty. When compression and probing both limit recall, the compression step comes first: at the observed rate, probing alone can't reach the target.
- The HNSW graph borrows FAISS's `offsets`/`neighbors` vectors as read-only numpy views (`rev_swig_ptr`) and holds a reference to the index, and flat node storage is viewed the same way (`hnsw_trace.node_vectors`); SQ/PQ storage is decoded per request with `reconstruct_batch`. Copying them cost the size of the graph plus the vectors (~400 MB at 1M × 64) for views that touch a few thousand nodes. The views must not outlive the index, which the owner reference guarantees.
- Saved runs are files the user keeps (download, `--save`, CI artifacts), not a server-side store: background results stay in memory, and a store would need its own retention and cleanup. The record is versioned JSON (`vectraudit.sweep-run` v1) whose identity is the index file's sha1 and the query set's SHA-256. Comparisons are setting by setting: recall only on the same query set, k and truth source; latency only when FAISS version, OS, machine and processor match. A p95 regression must exceed both a relative (20%) and an absolute (0.05 ms) threshold, since sub-millisecond single-threaded timings vary by tens of percent between identical runs. Exit code 3 (regression) is separate from 2 (target not met); when both apply, 2 wins.
- `resolve_search_params` passes the index's own `max_codes` through to the `SearchParametersIVF` it builds: FAISS's search-params path otherwise resets `max_codes` to unlimited, silently ignoring a scan cap set on the index and diverging from what a plain `index.search()` call would return for the same index and query.
- `core.search`'s `_as_query`/`search_batch` reject non-finite (NaN/Inf) vectors the same way `resolve_query`'s `_check_dim` does, instead of only checking dimension: a caller using `search()`/`GroundTruth` directly (bypassing `resolve_query`) previously got FAISS's empty-result sentinel for a NaN query instead of a clear error.
- The generic 500 handler in `server/app.py` includes a short reference id in both the client response and the log line (which always keeps the full traceback), but only echoes the exception's type/message to the client when `session.demo_limits` is `None`: `--demo-mode` deployments are public, so they get a generic message instead.
- The ground-truth corpus fingerprint (`settings.ground_truth_fingerprint`) hashes shape/dtype plus up to 4096 evenly spaced rows of `--vectors`, not the whole array: the corpus a sweep points at can be gigabytes, and this only needs to catch "you compared against a different file" (paired with `--baseline`'s own cost concern of not re-hashing the index unless needed), not verify it byte-for-byte. It's only computed for raw ground truth; reconstructed ground truth's identity is already the index's own sha1. A comparison is `comparable` (see `RunComparison.comparable`) only when at least one setting was actually judged; `sweep --baseline` and `runs diff` exit 4 (distinct from 3, a real regression) when it isn't, so a comparison that couldn't run is never mistaken in CI for one that ran and passed.
- Web relevance evaluation reuses the CLI's JSONL parser (`parse_judgements`) and metrics as a background job keyed by a hash of the judgements and settings; cancellation is checked between queries. The UI caps it at 10,000 queries and 5 MB of judgements (the CLI has no cap).
- Run history is one JSON file per run under `<cache root>/history/`, written atomically, newest 100 kept across indexes. It lives beside, not inside, the per-index projection directories, so `vectraudit cache clear` (which only removes `.npz` files there) never touches it. Demo mode and `disk_cache=False` turn it off; a failed write sets a warning instead of failing the finished job. Ids beyond 2^53 are stored as strings so a browser download stays lossless.
- Saved sweeps record the decision for a 0.95 recall target: the user's target lives only in the Tuner. The measurements are complete, so `compare_runs` doesn't depend on it; **Save run** still records the chosen target and budget.
- Frontend API types are generated from the FastAPI OpenAPI schema by `scripts/generate_api_types.py` (no npm dependency); CI fails when `schema.generated.ts` is stale. `types.ts` keeps short aliases plus UI-only refinements. `UserId` fields render as `number | string`, matching the large-id serializer.
- Searches and traces (`/search`, `/trace/ivf`, `/trace/hnsw`) run on the session's own small pool (`search_jobs`: 4 workers, 16 queued), not the background `jobs` runner: sharing it made searches wait behind sweeps, and each finished search evicted a slot of retained sweep results. The route polls `request.is_disconnected()` and cancels the job when the client leaves (a superseded query or closed tab): queued work never starts, running work stops at its next progress checkpoint, and a FAISS call already running finishes first. The response is built in the worker because it may compute IVF assignments.
- `fit_pca` accumulates the covariance in float64 over 8,192-row blocks instead of two full float64 copies of the sample: identical components, and at 20k × 384 peak RSS during PCA fell from +185 MiB to +127 MiB.
- Performance checks (`.github/workflows/performance.yml`, weekly and manual) measure this commit and a baseline ref (latest `v*` tag) on the same runner with `benchmarks/regression.py`, failing above the plan's absolute budgets or at 2x the baseline (1.25x for peak RSS) with a minimum absolute difference to ignore noise. The script uses only the public `Session` API and tolerates older signatures, so it can also measure the first prototype (commit `dcc9060`). The dataset is written by a child process so its temporaries don't count towards peak RSS.
- Firefox and WebKit run `e2e/workflow.spec.ts` (keyboard and non-WebGL workflows); the WebGL map specs stay Chromium-only. Specs that write server state (history renames) use per-browser settings, since the browsers share one server.
- On narrow frames the open sidebar is a modal dialog: focus moves into it, Tab cycles inside it, Escape closes it and focus returns to the Menu button.
- 2026-10-04: the project becomes a private commercial product (RetrievalScope PRD) under the name Vectraudit. The package, CLI, `VECTRAUDIT_*` env vars and cache directory were renamed in one step with no `faissight` compatibility shim, since nothing was ever published; releases go to a private GitHub release instead of PyPI. `benchmarks/regression.py` still imports `faissight` when measuring a pre-rename baseline.
- Licence is proprietary (`LicenseRef-Proprietary`); the `Private :: Do Not Upload` classifier makes PyPI reject an accidental upload. - 2026-10-09: A/A calibration (`evaluation/calibration.py`, `vectraudit calibrate`). - 2026-10-10: Cohort multiplicity control is opt-in (`cohorts.control: "bonferroni"`) rather than a silent change to the default: existing policies keep their meaning and hashes (`control` is dropped from `as_dict` while `"none"`), and a pass under one semantics never silently becomes a fail under another.
